# wirecheck

**"OpenAI-compatible" is not a specification.** It is a claim, and it is true in
the shape of the request and false in the details that break clients. `wirecheck`
points eleven probes at any `/chat/completions` endpoint and tells you exactly
where that endpoint differs from OpenAI — before the difference reaches
production as a blank panel or a `.length is not a function` from inside a stream
handler.

```
$ wirecheck --target cloudflare

cloudflare (@cf/meta/llama-3.3-70b-instruct-fp8-fast)
  = token-param      accepts max_tokens (HTTP 200) 1590ms
  ≠ unknown-param    silently IGNORES unknown top-level fields (reference rejects them with 400)
  = system-role      accepts the system role and honoured it 440ms
  = empty-content    returned content at a 16-token budget (finish_reason=stop) 733ms
  = finish-reason    reports truncation as finish_reason="length" 1080ms
  = usage-fields     usage present; also non-standard: neurons, prompt_tokens_details 418ms
  ≠ numeric-chunk    4 of 8 content deltas were NOT strings (saw string, number) — coerce with String()
  = stream-frames    clean framing: 12 data chunks, [DONE] present, no comments 1817ms
  = stream-usage     usage present on the final chunk 477ms
  = reasoning-leak   no thinking field in delta (saw: role, content) 4390ms
  ≠ error-shape      unknown model → HTTP 400, envelope { errors: [ … ] }
  — 3 divergences, 0 unsupported, 8 matching
```

A `≠` is not a complaint about the provider. It is a thing your client code has
to handle.

## What it actually found

Real results from the [measured matrix](MATRIX.md), generated by live calls:

**The same provider is not compatible with itself.** `gpt-4o-mini` and
`gpt-5.4-mini` are one endpoint, one account, one request builder. On
`gpt-5.4-mini`, `max_tokens` is a hard **HTTP 400**, not an ignored field — you
must send `max_completion_tokens`. And the `system` role is rejected outright;
it wants `developer`. Change a model string, break a client.

**Streamed content is not always a string.** Cloudflare Workers AI emits an
*unquoted JSON number* when a chunk is purely numeric, so a reply opening "1."
yields the JavaScript number `1`. Measured: 4 of 8 deltas. Every tutorial client
concatenates deltas, concatenation coerces, so this hides perfectly — until
something calls `.length`, `.slice()` or `.trim()` on a piece and throws.

**HTTP 200 can mean nothing happened.** Reasoning models bill internal thinking
against the *output* budget. Give one a tight budget and you get `200`,
`finish_reason: "length"` and an **empty content string**. Reproduced on local
`qwen3:8b` at a 16-token budget. Nothing errors. A client that trusts the status
code renders a blank panel, logs nothing, and cannot fall back — as far as it
knows, the call succeeded. The only robust client response is to treat empty
content as a thrown error.

**Some endpoints hand you the model's private scratchpad.** Ollama's `/v1`
endpoint ships `delta.reasoning` alongside `delta.content`. Render every string
you find in the delta and you publish the thinking to your users. Read
`content` by name; never iterate the delta.

## Install

Needs [Bun](https://bun.sh). No build step — the CLI is TypeScript run directly.

```bash
git clone https://github.com/Umojahene/wirecheck
cd wirecheck
bun install

export OPENAI_API_KEY=...          # or any other provider key
bun run src/cli.ts --list          # what's configured, and every probe
bun run src/cli.ts                 # probe everything configured
```

## Usage

`bun link` once to get the bare `wirecheck` command used below; otherwise every
example works as `bun run src/cli.ts …`.

```bash
wirecheck                                    # every configured target
wirecheck -t openai -m gpt-5.4-mini          # one target, specific model
wirecheck -t cloudflare -p numeric-chunk -v   # one probe, with evidence
wirecheck --url https://host/v1/chat/completions --model m --key-env MY_KEY
wirecheck --dry-run                          # call cost before spending it
wirecheck --json                             # machine-readable
wirecheck --markdown                         # the matrix, for pasting
```

Built-in targets: `openai`, `deepseek`, `openrouter`, `cloudflare`, `ollama`,
`xai`, `groq`, `together`, `mistral`. A bare `wirecheck` runs only the ones whose
keys are actually set, so it is useful immediately instead of printing a wall of
"missing env".

Adding a provider is a spec entry in [`src/targets.ts`](src/targets.ts) — url,
headers, default model — and nothing else. **If adding one requires touching a
probe, the probe is wrong.**

## The probes

| probe | the client bug it prevents |
|---|---|
| `token-param` | sending `max_tokens` gets a 400, not a truncation, on some models |
| `unknown-param` | whether one request body can be reused across providers |
| `system-role` | a silently dropped system prompt makes an agent ignore its instructions |
| `empty-content` | a 200 with empty content is indistinguishable from success by status |
| `finish-reason` | `finish_reason === 'length'` stops detecting truncation elsewhere |
| `usage-fields` | a missing usage block makes every cost number an estimate |
| `numeric-chunk` | a non-string delta throws in any client touching a piece |
| `stream-frames` | keepalive comments break naive parsers; no `[DONE]` hangs clients |
| `stream-usage` | without streamed usage, streaming costs are guesses |
| `reasoning-leak` | rendering the whole delta publishes the model's thinking |
| `error-shape` | fallback branches on status and `error.message`; neither is standard |

## This tool's own worst bug

Worth stating plainly, because it is the failure mode the tool exists to catch
and it happened *in* the tool.

Run against two accounts at zero balance, the first version reported eleven
confident findings per provider: *"accepts max_tokens (HTTP 402)"*, *"rejects the
system role (HTTP 402)"*, *"unknown model → HTTP 402"*. Every one was false. The
endpoints had not processed a single request — `402` means the account was
refused before the body was ever read. The probes saw "not a 400" and concluded
"supported."

The fix is `preflight()` in [`src/run.ts`](src/run.ts): one minimal call per
target, and any of `401/402/403/407/429` marks it **unreachable** and skips every
probe with the reason. A `400` about `max_tokens` still counts as reachable —
that is an endpoint reading your body and objecting to it, which is exactly what
should be measured next. Regression tests cover all four blocking statuses and
the three non-blocking ones.

A second, smaller case: `stream-usage` hardcoded `max_tokens`, so on a model
that rejects that parameter it read the resulting 400 as *"rejects
stream_options"* — a confident, wrong finding about a feature it had never
reached. It now negotiates the budget parameter first and only blames
`stream_options` if the error actually mentions it.

And one premise of my own that the measurements killed: `unknown-param` was
written asserting that OpenAI *ignores* unknown top-level fields and that
stricter endpoints were the divergent ones. The reference rejects them —
`HTTP 400 Unrecognized request argument supplied`. Strict is the reference; the
verdict logic was backwards and is now the other way round.

## Design

**Probes report a divergence, not a pass or fail.** There is no specification to
pass. There is only OpenAI's observed behaviour and the ways other endpoints
differ. Divergences therefore do not fail CI — making them fail would punish you
for adding a provider. The exit code is non-zero only when *no* target produced a
conclusive result.

**Evidence is redacted before it can be printed.** Output is meant to be pasted
into issues, so anything shaped like a credential is stripped on the way out,
recursively through evidence objects. Deliberately aggressive: a false positive
costs a line of output, a false negative publishes a secret.

**The suite is tested offline.** 39 tests, no API calls, ~370ms. The cases that
matter — a numeric delta, a mid-stream usage block, a frame split across two
network reads, an endpoint at zero balance — are ones a live endpoint produces on
its own schedule, not the test suite's. Fixtures are modelled on frames observed
in real runs.

```bash
bun test          # 39 tests, no network, no keys needed
bun run typecheck
```

## Limits

- **Divergence is measured against OpenAI**, because something has to be the
  reference. That is a choice, not a judgement.
- **One model per column.** A finding is about a (endpoint, model) pair, never a
  provider in general — see the two `openai` columns.
- `system-role`'s "accepted but not honoured" verdict is about
  instruction-following, not transport. A small local model failing it is not an
  API divergence, and the finding says so.
- Local timings come from an 8 GB M1 at roughly 1.6 tokens/sec. Evidence of
  behaviour, not of speed.
- Probes cost about 12 model calls per target, all with tiny budgets. Use
  `--dry-run` to see the cost and `--max-calls` to cap it.
